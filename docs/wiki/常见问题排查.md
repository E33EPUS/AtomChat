**先按症状找，再按日志定位。** 所有排查都围绕一份日志：`.minecraft/logs/latest.log`（服务端是 `logs/latest.log`）。

## 面板打不开 / 按 T 没反应

1. **JAR 对不对**：Fabric 版只能配 Fabric Loader、NeoForge 版配 NeoForge、Forge 版配 1.20.1 + Forge 47+；装错加载器的 JAR 不会加载。也确认 Java 版本（Fabric / NeoForge 要 21+，Forge 1.20.1 要 17）。
2. **是不是被别的界面占着**：`Y` 键只在当前没有打开任何界面时才会拉起面板。
3. **看日志**：搜索 `atomchat`，有没有加载失败 / 缺少依赖（`fabric-api` 是 Fabric 版的必需项）。
4. **按键冲突**：`选项 → 控制 → 按键绑定 → AtomChat` 里确认 `打开 AtomChat`（默认 `Y`）没被别的模组抢走；原版聊天键（`T` / `/`）被其它模组改写时也可能失效。

## 文件选择窗口打不开（点图片 / 头像 / 壁纸没反应）

这是 0.2.9 修掉的一个兼容性问题：某些模组（实测触发者是 **TerraFirmaCraft / TFC**）会在非常早的阶段初始化 AWT，而 MC 客户端主类 `Main` 会把 `java.awt.headless` 设成 `true` —— 谁先碰到 AWT，这个属性就被锁死。结果是 AtomChat 弹出文件选择窗口时抛 `HeadlessException`，异常又被日志吞掉，玩家只看到「点了没反应」。

**0.2.9 起**：由 Mixin 插件在 Mixin 准备阶段（早于所有模组构造，也早于 `Main`）抢先认领 AWT。万一仍然拿不到：

- 日志里会有一条 `ERROR` 级记录，写明原因；
- 游戏内会直接弹一条提示（`atomchat.picker.headless`）。

排查时搜日志关键词：`HeadlessException`、`java.awt.headless`、`Image picker`。若你用的是 0.2.8 或更早版本，**升级到 0.2.9 即可**。

## 消息显示成灰色

灰色 = 客户端无法确定那一行是不是玩家消息，保守地当成系统消息渲染（这是**设计**，不是猜错）。常见于昵称 / 花名插件用了客户端不认识的消息格式。

缓解办法：在 `config/atomchat/atomchat-client.json` 里手写识别模板 —— `chatTemplates`（公屏）与 `whisperTemplates`（私聊），占位符支持 `{name}` `{display_name}` `{prefix}` `{suffix}` `{sep}` `{content}`（`{content}` 恰好出现一次）。改完**重开聊天界面**即生效，不用重启游戏。

## 图片相关

图片不显示、老图变破图、上传失败 → 看 [图片消息与传输路线](图片消息与传输路线)的排错表。

## 面板整块变黑（仅旧版本）

0.2.8 之前，Forge 1.20.1 上打开面板后可能整屏变黑（游戏不崩、还能打字）。根因是模糊 pre-pass 的 raw GL 状态写回与 1.20.1 的缓存门控 setter 不一致，**0.2.8 已修**；0.2.8 起若模糊 pass 出事，会退成不透明实色面板并打一条带 GL 错误码的节流警告，不再静默变黑。

## 已知不受支持

- **Linux / macOS**：JAR 内只有 Windows x64 的 Skija 原生库，面板无法启动。
- **Quark**：装了 Quark 时表情菜单不显示，正在尝试兼容。
- **其他 MC 版本 / 加载器**：目前只有 Fabric / NeoForge 1.21.1 与 Forge 1.20.1。

## 报 bug 请带上这些

1. 模组版本（如 `v0.2.9`）+ 加载器与版本 + MC 版本；
2. 是**单人 / 局域网主机 / 专用服务器**，服务端是否也装了 AtomChat；
3. 复现步骤（越短越好：做了什么 → 期望什么 → 实际什么）；
4. `.minecraft/logs/latest.log`（或崩溃报告 `crash-reports/`）；
5. 触发时的截图 / 录屏（界面类问题很有用）；
6. 如果和图片 / 下发有关，把日志里的 `Stored hosted media`、`Failed to upload image`、下发失败原因一并贴上。
