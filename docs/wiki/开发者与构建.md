## 仓库结构

| 分支 | 内容 |
|---|---|
| `Fabric-1.21.1` | Fabric 1.21.1 源码；**tag 与 Release 从这里打** |
| `NeoForge-1.21.1` | NeoForge 1.21.1 源码 |
| `Forge-1.20.1` | Forge 1.20.1 源码（Java 17） |
| `Master` | 用户文档：README（中 / 英）、`docs/` 平台文案、本 Wiki 的源文件 |

三个源码分支**功能同源**：同一份实现，按加载器 API 适配。这意味着一个改动要在三个分支各落一次 —— 这是当前结构的已知成本，收敛方向见文末「技术债」。

## 构建与测试

```bash
./gradlew.bat build   # 构建 + 跑测试
./gradlew.bat test    # 只跑测试
```

- 产物在 `build/libs/`，文件名形如 `atomchat-Fabric-1.21.1-<version>.jar`；
- Fabric / NeoForge 分支用 **JDK 21**；Forge 1.20.1 分支用 **JDK 17**；
- Forge 分支会额外产出一个 `-slim` JAR（不内嵌依赖，仅供开发），**发版用不带 `-slim` 的那个**；
- 版本号在 `gradle.properties` 的 `mod_version`，三端保持一致。

测试是 **JUnit 5**，只覆盖**纯逻辑层**（不需要启动游戏）：动画时长与缓动、布局数学、消息解析与分类、表情包存储、文件名清洗、AWT 状态判定、服务端表情迁移等。当前三端各 **472 项**。CI 跑在 Linux 上，所以 `skija-linux-x64` 是**测试域**依赖（永不进产物）。

## 代码地图

主包 `com.atom.chat`：

| 包 | 职责 |
|---|---|
| `screen` / `page` | `AtomChatScreen` 是编排层（Skia 自绘面板），页面（公屏、会话、档案、设置）在 `page` |
| `ui` | 布局 / Token / 动效常量与面板组件（表情面板、常用语面板） |
| `render` / `text` | Skia 绘制封装、富文本与可点击 span、聊天文本改写 |
| `chat` | 消息捕获 / 分类 / 呈现管线，私聊与 tell-click 解析，身份识别 |
| `net` | 三个伴生通道：媒体托管、头像同步、配置屏；载荷定义与编解码 |
| `pack` | 服务端下发包：构建、差量同步、客户端存储与迁移 |
| `image` / `emote` / `avatar` / `wallpaper` | 图片加载与缓存、表情包持久化、头像渲染与裁剪、壁纸 |
| `config` / `settings` | 客户端与**服务端**配置、设置项目录、服务端配置屏 |
| `mixin` | 原版聊天捕获、IME / 建议框接入、AWT 抢注插件 |
| `util` | 缓存目录、文件选择器、文件名清洗、AWT 状态 |

> Fabric 分支有少数类住在 `net.minecraft.client.gui.screen` 包下（需要访问包私有成员）；NeoForge / Forge 分支的同名类在 `com.atom.chat.screen`。这是三端目录结构上唯一的显著差异。

## CI 与发版

| 工作流 | 触发 | 做什么 |
|---|---|---|
| `build.yml` | 三个源码分支的 push / PR | 装 Skija 的 Linux 系统依赖 → `./gradlew build`（含测试） |
| `release.yml` | 推送 `v*` 标签（在 `Fabric-1.21.1` 上打） | 三端各自构建 → 校验三端 `mod_version` 与 tag 一致 → 建一个 GitHub Release 并挂上三个 JAR → 发布到 CurseForge；Modrinth 发布已接好但未启用（缺 `modrinth_project_id` 与 `MODRINTH_TOKEN`） |

发版清单（当前流程）：改三端 `gradle.properties` 的 `mod_version` → 三端各写 CHANGELOG / RELEASE_NOTES（中英双块）→ 推送三端 → 在 Fabric 分支打 `vX.Y.Z` 标签并推送 → 看 `release.yml` 是否全绿。

## 文档与翻译

- 用户文档：`Master` 分支的 `README.md`（中文）/ `README_EN.md`（英文），两份**逐节镜像**，改一份要同步改另一份；
- 平台文案：`docs/mcmod-description.md`（中文，mcmod 的 `[h1=]` 语法）、`docs/curseforge-description.md`（英文，CurseForge 用）、`docs/modrinth-description.md`（英文，与 CF 共用正文，仅去掉徽章行）；三者与 README 是**同源素材**，改功能时一起对齐；
- 本 Wiki：源文件在仓库的 `docs/wiki/`，推送后生效（源是唯一真源，改源再推，别直接在网页上改）；
- 界面翻译：`src/main/resources/assets/atomchat/lang/zh_cn.json` 与 `en_us.json`，新增文案两处都要加。

## 技术债（已记录，尚未动手）

| 项 | 现状 | 打算 |
|---|---|---|
| 三端手工同步 | 一个改动要在三个分支各落一次（含 CHANGELOG） | 收敛为**单分支多目标**结构：共享代码放一起，平台差异进各平台目录，CI 遍历目标矩阵构建 |
| 映射不统一 | Fabric 用 Yarn，NeoForge / Forge 用官方映射 —— 同一份逻辑在两端名字不同 | 统一到官方映射，这是上面那步的前置条件 |
| 历史遗留 | `Fabric` 的少数类住在 `net.minecraft` 包下 | 合并时一并整理 |
